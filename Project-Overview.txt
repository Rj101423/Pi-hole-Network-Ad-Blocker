AD-BLOCKER PROJECT

Project Name:
Self-Hosted Network Ad & Tracker Blocker

Purpose:
The purpose of this project is to create a functional, self-hosted ad and tracker blocking solution while developing practical IT skills in networking, DNS, Linux system administration, network security, remote server administration, Bash scripting, troubleshooting, and technical documentation.

Project Goal:
Build and configure a self-hosted network ad and tracker blocking system using an older Toshiba laptop. Install Ubuntu Server and Pi-hole to provide DNS-based filtering for devices connected to the local network. Configure SSH for remote server administration and a UFW firewall to secure network traffic. Develop a Bash script to monitor server performance and verify the status of important services. Test and troubleshoot the system to ensure proper connectivity, DNS resolution, ad blocking, and server functionality while documenting the installation, configuration, troubleshooting, and testing processes.

UFW FIREWALL CONFIGURATION
========================================

Purpose:

UFW (Uncomplicated Firewall) was configured to improve the security of my Ubuntu Server by controlling incoming and outgoing network traffic. The firewall allows the connections needed for Pi-hole DNS filtering, web dashboard access, and SSH remote administration.

Firewall Software:
UFW (Uncomplicated Firewall)

Initial Firewall Status:
Inactive

Initial Verification Command:
sudo ufw status verbose

Firewall Configuration:

After checking the firewall's initial status, I configured rules to allow the necessary network services before activating the firewall.

Firewall Rules:

22/TCP - SSH Remote Access

53/UDP - Pi-hole DNS Requests

53/TCP - Pi-hole DNS Requests

80/TCP - Pi-hole Web Dashboard (HTTP)

443/TCP - HTTPS Traffic

Commands Used:
sudo ufw allow 22/tcp
sudo ufw allow 53/udp
sudo ufw allow 53/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

Firewall Verification:

After configuring the firewall rules, I reviewed the rules and verified that UFW was active.

Commands Used:
sudo ufw show added
sudo ufw status verbose

Final Firewall Status:
Active

Default Firewall Policies:
Incoming: Deny
Outgoing: Allow

Testing and Verification:

After activating the firewall, I verified that SSH remote access and Pi-hole services continued functioning correctly.

Result:

The UFW firewall was successfully configured and activated. The server now restricts incoming network traffic while allowing the services required for remote administration and DNS-based ad blocking.

## SERVER HEALTH CHECK AUTOMATION

As part of my Pi-hole Ad Blocker project, I developed a Bash script to simplify monitoring and maintaining my Ubuntu Server.

The script performs seven system checks, including displaying the server's hostname, uptime, disk usage, and memory usage. It also verifies the status of Pi-hole DNS filtering, SSH remote access, and the UFW firewall.

I created the script using Windows Notepad and transferred it to Ubuntu Server using SCP over an SSH connection.

During testing, I encountered several issues involving Windows and Linux line endings, incomplete file transfers, and Linux file permissions. I successfully troubleshot these issues and updated the script to run correctly.

After completing the troubleshooting process, I performed a final test and confirmed that all seven checks executed successfully.

This addition to my project allowed me to gain hands-on experience with Bash scripting, Linux system administration, secure file transfers, troubleshooting, and basic server monitoring.
