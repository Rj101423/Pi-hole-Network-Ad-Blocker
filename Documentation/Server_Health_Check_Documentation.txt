# SERVER HEALTH CHECK SCRIPT DOCUMENTATION

## 1. PURPOSE

The purpose of this script is to make it easier to monitor the health and performance of my Ubuntu Server.

Instead of manually entering multiple commands, I created a Bash script that displays important system information and checks whether the services needed for my Pi-hole ad blocker are running.

This helps me identify potential problems with my server and makes routine maintenance easier.


## 2. SOFTWARE AND TOOLS

- Ubuntu Server 26.04.1 LTS
- Bash
- Windows PowerShell
- OpenSSH
- SCP (Secure Copy)
- Pi-hole
- UFW (Uncomplicated Firewall)
- Windows Notepad


## 3. SCRIPT INFORMATION

Script Name: server_health_check.sh

Script Type: Bash Shell Script

Development Environment: Windows 11 using Notepad

Execution Environment: Ubuntu Server

Script Location on Ubuntu: /home/serveradmin/server_health_check.sh

The script performs the following checks:

- Server hostname
- System uptime
- Disk usage
- Memory usage
- Pi-hole DNS filtering status
- SSH service status
- UFW firewall status


## 4. SCRIPT COMMANDS AND FUNCTIONS

I created a Bash script to automatically display system information and check the status of important services on my Ubuntu Server.

The script uses the following commands:

- `#!/bin/bash` — Specifies that the script should run using the Bash shell.
- `echo` — Displays headings and messages to organize the script's output.
- `hostname` — Displays the server's hostname.
- `uptime` — Shows how long the server has been running and its current system load.
- `df -h /` — Displays the amount of disk space used and available on the server's main filesystem.
- `free -h` — Displays memory and swap usage in a readable format.
- `sudo pihole status` — Checks whether Pi-hole's DNS service is running and whether blocking is enabled.
- `systemctl is-active ssh` — Checks whether the SSH service is active.
- `sudo ufw status` — Displays the firewall's current status and configured rules.

By combining these commands into one script, I can check my server's system resources and important services without having to enter each command separately.

## 6. TROUBLESHOOTING

During the development and testing of my Bash script, I encountered several issues that required troubleshooting.

### Issue 1: Bash Interpreter Error

When I first attempted to execute the script on Ubuntu, I received the following error:

`/bin/bash^M: bad interpreter: No such file or directory`

This occurred because I created the script using Windows Notepad, which saved the file with Windows-style (CRLF) line endings instead of Linux-style (LF) line endings.

**Solution:**

I used the following command to remove the Windows carriage-return characters:

`sed -i 's/\r$//' ~/server_health_check.sh`

After running this command, Ubuntu was able to execute the script.

### Issue 2: Incomplete Script Output

During testing, the script initially displayed only the server hostname and uptime instead of all seven system checks.

I used the `cat ~/server_health_check.sh` command to inspect the script's contents and discovered that the copy on Ubuntu was incomplete.

**Solution:**

I verified that the original Windows script contained all the necessary commands and transferred the complete file again using SCP.

After correcting the line endings, the script displayed all seven sections.

### Issue 3: Pi-hole Permission Warning

When I tested the complete script, Pi-hole displayed a permission warning because my Ubuntu user could not read `/etc/pihole/pihole.toml`.

Although Pi-hole reported that DNS filtering was enabled, the warning indicated that the status information might not reflect the current configuration.

**Solution:**

I updated the script by changing:

`pihole status`

to:

`sudo pihole status`

This allowed the command to read Pi-hole's configuration using administrator privileges.

After transferring and testing the updated script, the permission warning no longer appeared.
